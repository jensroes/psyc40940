Assignment Instructions

Timing note: The deadline falls shortly after the university closure period. You are strongly advised to have a working version of your RMarkdown report and Shiny dashboard before the winter break. Teaching staff availability during the closure period will be limited; support should be sought during scheduled sessions, tutorials, and office hours before the break.

For this assessment you will submit a portfolio combining an RMarkdown report, a Shiny dashboard, and reflective commentary. The purpose is to demonstrate mastery across all module learning outcomes.

Choose one complex behavioural dataset, meaning data related to human behaviour such as psychological experiments, survey responses, reaction times, decision-making patterns, or social media behaviour.

  1. Static visualisations: produce four different visualisation types, use publication-quality formatting, and comment on your design choices.
  2. Interactive dashboard: use Shiny with a maximum of three tabs, allow user input such as variable selection or filters, include at least two interactive plots, and support exploration and insight generation into human behaviour. Interactive plots may include plot-level interactivity, such as hover, zoom, or selection, and/or Shiny-reactive plots that update in response to user inputs such as filters or variable selectors. The key requirement is that the dashboard supports meaningful exploration of the behavioural data.
  3. Reflection section: discuss challenges, design decisions, and practical constraints, linking your work to principles of effective visualisation, data communication, and transparency.

Static visualisations and reflection should be included in the same RMarkdown document. The Shiny dashboard must be submitted as a separate Shiny application, either as a single app.R file or as an app folder containing app.R and any required supporting files. The RMarkdown report should render separately to HTML or PDF.

Submission Requirements: Dropbox Submission

Submit a single zip archive to the appropriate Dropbox before 2 pm on the deadline day. Ensure that you receive and keep the email confirming submission.

The zip archive must contain exactly one RMarkdown file, the HTML generated from this file, the RStudio project file, the separate Shiny app file or folder, the relevant data file(s), and any supplementary files such as bibliography files, helper scripts, or custom R functions. HTML is the expected rendered report format for this module because it supports interactive and dynamic outputs more naturally than PDF. If you have a good reason to render the report to PDF instead, this is acceptable, but the RMarkdown source must still be included.

The work must be reproducible. Markers must be able to reproduce your report in full from the RMarkdown source code, the separate Shiny app file or folder, and other submitted files. Your RMarkdown report and Shiny app should include a clear setup section listing and loading all required packages. At the end of the RMarkdown report, include the output of sessionInfo() or an equivalent package/version summary to support reproducibility. If a dataset is too large to submit or cannot legally be redistributed, include a stable URL or DOI, clear download/access instructions, and code that imports or prepares the data where possible. You must explain this in the report.

Do not put your name or N number anywhere in the report, Shiny app, filenames, RStudio project name, file paths, rendered output, or submitted documentation unless specifically instructed to do so by the module leader.
